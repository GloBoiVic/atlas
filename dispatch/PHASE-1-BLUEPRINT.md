## Implementation Blueprint — Atlas Phase 1 Reference Strategy

### Outcome
- **Confirmed (high):** Build the smallest backend-only Phase 1 vertical slice that explicitly registers, validates, versions, persists, loads, and deterministically evaluates the EMA Sweep Engulfing Strategy through a pure public Strategy contract under the `backend.*` namespace.
- **Confirmed (high):** The slice includes typed parameters; immutable StrategyVersion provenance; a stable source fingerprint; completed EUR/USD MID 15m bar inputs; deterministic, JSON-serializable state; EMA/ATR calculations; and long, short, NO_ACTION, state-transition, and reference-window expiry behavior.
- **Confirmed (high):** Exclude OANDA and all credentials, historical ingestion/aggregation, Instrument persistence, DatasetSnapshot/Experiment/UI, Risk sizing, TradeIntent persistence, Orders/Fills, execution, Deployment/runtime state persistence, plugin discovery, multiple Strategies, and frontend/API work.
- **Confirmed (high):** Phase 1 ends at `StrategyEvaluation(decision, next_state)`. Phase 3 will convert an actionable StrategyDecision into a canonical TradeIntent and will resolve executable entry-dependent values; Phase 8 will persist Deployment Strategy state and enforce runtime scheduling/recovery.

### Agreed language
- **Strategy:** Long-lived methodology identity; Phase 1 has exactly one, `ema-sweep-engulfing`.
- **StrategyVersion:** Immutable persisted provenance for one executable methodology snapshot. Parameter values are not part of version identity.
- **StrategyDefinition:** Immutable metadata and typed schemas exposed by a registered Strategy implementation: identity, parameters, timeframe, warm-up, capabilities, state schema version, and source-file allow-list.
- **StrategyContext:** Pure evaluation input containing Atlas-supplied UTC evaluation time, canonical Instrument identity, ordered completed bars, current Position direction, and warm-up/exposure permission. It contains no account, Risk, broker, database, environment-mode, or wall-clock access.
- **StrategyState:** Versioned minimal methodology continuation state. For this Strategy: phase, direction, reference prices/time, optional sweep time, count of received canonical completed 15m evaluation bars processed since reference selection, and last evaluated bar end; indicator objects and complete bar history are excluded.
- **StrategyDecision:** `NO_ACTION`, `OPEN_LONG`, or `OPEN_SHORT` for this phase, with deterministic rationale and, when opening, a proposed stop plus a target methodology. It is not a TradeIntent or Order.
- **Target methodology:** An immutable `R_MULTIPLE` proposal carrying `1.7`; no target price is fabricated from the confirmation close. A later caller supplies the actual executable entry and resolves `entry ± 1.7 × abs(entry - stop)`.
- **Source fingerprint:** Lowercase SHA-256 over an explicit, sorted allow-list of behavior-owning UTF-8 source files, using relative POSIX paths and length-delimited raw bytes. It is independent of absolute checkout path, git metadata, timestamps, parameter values, and file enumeration order.
- **Completed bar:** Canonical UTC interval `[start_time, end_time)`, marked complete, with `end_time <= evaluation_time`; Phase 1 Strategy analysis accepts EUR/USD, MID, 15m only. Developer interest in 5m or 1m evaluation is **deferred** and does not authorize configurable/multiple timeframes, resampling, or generalized implementation in this phase.
- **Reference expiry window:** Selecting a reference candle establishes that bar as the fixed reference and starts a window comprising exactly the next five received canonical completed 15m evaluation bars. These bars are counted as `W1`–`W5`; elapsed wall-clock time and missing intervals do not consume a slot, and gaps must never be filled or fabricated. Sweep and confirmation may occur on any received bar in that window; sweep and confirmation may occur on the same window bar. The reference candle itself is not one of the five and cannot also serve as its own sweep/confirmation candle.
- **Indicator warm-up:** For an ordered supplied sequence of completed MID bars, EMA-100 first becomes valid on supplied bar 100. The first supplied bar has no True Range because no previous close may be fabricated; ATR-14 first becomes valid on supplied bar 15. Both indicators are therefore available from supplied bar 100 onward, and the Strategy definition declares `warm_up_bars=100`.

### Decisions
- **Pure boundary — confirmed (high):** Put canonical value objects and enums in `backend/domain/market_data.py` and `backend/domain/strategy.py`; put the public `Strategy` protocol and registration metadata in `backend/strategies/contract.py`. Domain and contract modules must not import FastAPI, SQLAlchemy, settings, persistence, runtime, or integrations.
- **Evaluation signature — assumed (high):** `evaluate(context, parameters, state) -> StrategyEvaluation`. Inputs and returned objects are immutable. Evaluation performs no I/O and never mutates the supplied state. `StrategyEvaluation` always contains exactly one decision and one next state.
- **Input frontier — assumed (high):** A contract-level context validator rejects naive/non-UTC times, unordered or duplicate intervals, incomplete bars, bars ending after the evaluation frontier, invalid OHLC geometry, wrong Instrument/timeframe/price component, insufficient lookback when exposure is enabled, and a current bar not newer than `state.last_evaluated_bar_end`.
- **Duplicate semantics — confirmed/assumed (high):** Re-evaluating the same or an older completed bar raises `DuplicateBarEvaluationError`; it does not return NO_ACTION or alter state. This provides a local guard, while durable exactly-once scheduling remains Phase 8.
- **Warm-up and exposure boundary — confirmed (high):** Definition declares `warm_up_bars=100`. When `context.exposure_allowed=False`, evaluation returns NO_ACTION, advances only the duplicate-detection frontier, and returns `SEARCHING` with all pending setup fields cleared: it neither selects a reference nor creates or advances a setup, and it never emits OPEN. Indicator calculation may still be deterministic, but it creates no methodology continuation state. `exposure_allowed=True` with fewer than 100 ordered completed MID bars is an input error, not silent warm-up; exactly 100 bars is sufficient for both indicators. The supplied sequence is the calculation history: implementations must not silently prepend, synthesize, or substitute an earlier close or bar.
- **Parameters — confirmed (high):** Use frozen typed domain values, not free-form dictionaries: EMA period `100`, ATR period `14`, stop buffer `Decimal("0.5")`, target R `Decimal("1.7")`, expiry window `5`. The expiry value is measured from reference selection, not from sweep. Positive integer/Decimal constraints are enforced; unspecified maxima remain absent rather than invented. Serializable schema descriptors include key, label, type, default, nullable min/max, allowed values, and description. Runtime value changes do not alter the source fingerprint or create a StrategyVersion.
- **Numeric/time representation — confirmed (high):** Use `Decimal` for OHLC, indicators crossing the Strategy boundary, stop, and target geometry; use timezone-aware UTC `datetime`. No binary float is authoritative.
- **EMA-100 — confirmed (high):** Seed the first EMA with the arithmetic mean of closes from supplied completed bars 1–100. For each supplied bar from 101 onward, recursively calculate `EMA_t = EMA_(t-1) + alpha × (close_t - EMA_(t-1))`, where `alpha = Decimal(2) / Decimal(100 + 1)`. EMA is unavailable for supplied bars 1–99. Do not substitute a library-specific seed or smoothing convention.
- **ATR-14 — confirmed (high):** The first supplied bar has no valid True Range. For each supplied bar from bar 2 onward, calculate `TR_t = max(high_t - low_t, abs(high_t - close_(t-1)), abs(low_t - close_(t-1)))`. Seed ATR on supplied bar 15 with the arithmetic mean of the first 14 valid TR values (bars 2–15). From supplied bar 16 onward apply Wilder RMA as `ATR_t = ATR_(t-1) + (TR_t - ATR_(t-1)) / Decimal(14)`, equivalently alpha `1/14`. ATR is unavailable for supplied bars 1–14. Never fabricate an initial previous close or treat the first bar's `high-low` as valid TR.
- **Indicator fixture authority — confirmed (high):** Indicator tests must use committed, literal Decimal golden fixtures whose expected values are derived independently of the implementation. Fixtures must cover the seed and first recursive value for each indicator, gap-driven True Range branches, and exact warm-up boundaries. Assertions use exact Decimal equality—no binary floats, approximate tolerances, or expected values generated by the implementation/library under test.
- **State machine — confirmed (high):** Persist only `SEARCHING`, `REFERENCE_IDENTIFIED`, and `AWAITING_CONFIRMATION`; `ENTRY_DECISION` is a transient output. Selecting reference candle `R` leaves the state active with zero window bars elapsed. The next five received canonical completed 15m evaluation bars are `W1` through `W5`. Each received and processed window bar advances the elapsed count whether or not a sweep has occurred; wall-clock time and missing 15m intervals do not advance it, consume a slot, or authorize filling/fabricating a bar. Sweep and confirmation may occur on any `W1`–`W5`, including both on the same bar. Confirmation on `W5` produces a valid OPEN decision. If processing `W5` does not produce OPEN—including a first sweep on `W5` without confirmation—reset to `SEARCHING`; `W5` is consumed only as the final window bar and must not be reconsidered as a new reference. Reference search resumes with the next received completed evaluation bar (`W6`) or a later received bar. An OPEN is a transient output whose `next_state` is reset to `SEARCHING` with the current frontier; a later bar may be eligible for reference selection only if the caller still supplies `Position=FLAT`, while Phase 3 Position truth will normally prevent that after entry. Whenever current Position is non-FLAT, evaluation returns NO_ACTION, advances only the duplicate-detection frontier, clears all pending setup fields, remains `SEARCHING`, and neither selects a reference nor emits OPEN.
- **EMA trend timing — confirmed (high):** Evaluate the EMA trend relation only while `SEARCHING` to decide whether the current completed bar qualifies as a new reference. Once selected, the fixed unswept reference remains valid for its five-received-bar window even if price later crosses the EMA. After a sweep, the pending setup likewise remains valid through that same window. Do not recalculate trend as an active-setup validity condition and do not emit a pre- or post-sweep trend invalidation/reset.
- **Decision structure — confirmed (high):** OPEN decisions contain direction, confirmation time, stop price from confirmation-candle low/high and ATR buffer, `R_MULTIPLE` target proposal, and structured deterministic rationale containing the trend relation established at reference selection, reference/sweep/confirmation times and levels, ATR, and stop inputs. NO_ACTION carries a stable reason code. CLOSE_POSITION and UPDATE_PROTECTION remain canonical future actions but are not emitted or implemented here.
- **Persistence/migration — confirmed (high):** A Phase 1 Alembic migration is required because StrategyVersion provenance is durable source-of-truth, not temporary registration data. Add only `strategies` and `strategy_versions`; do not add `strategy_states`, Instruments, Experiments, Deployments, or trading tables.
- **Persistence shape — assumed (high):**
  - `strategies`: UUID PK, unique stable key, human name, description, UTC creation timestamp.
  - `strategy_versions`: UUID PK; restricted FK to Strategy; positive per-Strategy version number; 64-character lowercase SHA-256; implementation key; JSONB parameter schema, context timeframes, capabilities, source manifest, and exact UTF-8 source snapshot; primary timeframe; nonnegative warm-up bars; positive state schema version; UTC creation timestamp; nullable caller-supplied git commit SHA.
  - Unique `(strategy_id, version_number)` and `(strategy_id, source_fingerprint)` constraints. JSON arrays are stored in canonical sorted order by the mapper/service.
  - A PostgreSQL trigger rejects UPDATE and DELETE on `strategy_versions`; the SQLAlchemy repository exposes create/read only. Strategy deletion remains FK-restricted while versions exist. Migration downgrade may drop the new tables and is the only planned destructive rollback.
- **Version registration — assumed (high):** Explicit in-process registry, with no import scanning or entry points, contains one registration. Validation returns a validated definition. A focused repository transaction creates the Strategy identity if absent, locks it while allocating the next version number, returns the existing row for the same fingerprint, and inserts a new immutable row for a different fingerprint. No automatic database writes occur at module import, API startup, or runtime startup.
- **Source snapshot — assumed (medium):** Fingerprint and archive only explicitly allow-listed Strategy/indicator source files beneath `backend/`; reject symlinks, path traversal, non-UTF-8 files, and duplicates. Registration-time filesystem reads are allowed; evaluation-time reads are forbidden. Git SHA is supplied by the caller—Atlas does not invoke git. Archived source is provenance only and is never dynamically executed.
- **Version loading — assumed/deferred (medium):** Phase 1 may execute a persisted StrategyVersion only when the local registration's computed fingerprint equals the row. A mismatch raises `StrategyVersionUnavailableError`; it must never run changed code under an old version identity. Packaging/loading archived historical implementations must be resolved before Phase 3 needs to rerun old versions.
- **State errors — confirmed/assumed (high):** State JSON has `schema_version=1` and canonical Decimal strings/UTC timestamps. Malformed JSON, wrong root type, unknown schema version, missing/extra fields, invalid enum/value, naive timestamp, impossible phase/field combinations, or out-of-range elapsed count raises `StrategyStateError`. Evaluation does not catch-and-reset it, produce NO_ACTION, or advance state. In future PAPER/LIVE use this blocks new exposure and requires explicit recovery.
- **Unexpected evaluation failure — confirmed (high):** Contract/input/state failures are typed and actionable. Unexpected implementation exceptions propagate as `StrategyEvaluationError` with no fabricated decision/state. NO_ACTION is a business outcome, never an error substitute.
- **Dependencies/security — confirmed (high):** Use the Python standard library plus existing project dependencies only; add no package. Strategy code imports no settings and requires no `ATLAS_*` or OANDA variables. Source snapshots must contain code only; if an allow-listed source file contains a secret, registration must stop rather than persist it (review plus a narrow obvious-secret detector; no claim of exhaustive secret scanning).
- **Rollback — assumed (high):** Reverting Strategy code never edits an existing StrategyVersion; it either matches an existing fingerprint or creates another version. Application rollback must retain migrations and existing rows. Database downgrade is permitted only when intentionally discarding all Phase 1 provenance.

### Constraints and risks
- **Indicator history boundary — confirmed (high):** The approved formulas resolve indicator initialization and smoothing. Because the first supplied bar intentionally has no TR, ATR-14 requires 15 supplied bars, while EMA-100 requires 100; the joint Strategy warm-up remains exactly 100 supplied completed bars. Builders must expose insufficient history explicitly and must not use a library default that changes seed, True Range, smoothing, or warm-up behavior.
- **Active-reference stability — confirmed (high):** EMA trend is a reference-selection predicate only. Trend changes during `REFERENCE_IDENTIFIED` or `AWAITING_CONFIRMATION` neither replace nor invalidate the setup. Window expiry occurs only when the fifth received canonical completed 15m evaluation bar after reference selection is processed without OPEN; elapsed wall-clock time and interval gaps do not expire it. The approved exposure-permission and Position boundaries independently clear pending state as specified above.
- **Historical executable retention — deferred (medium):** The source snapshot proves provenance but is deliberately not an executable plugin/archive loader. Before old StrategyVersions can be selected by Experiments, decide whether Atlas retains versioned local modules or introduces a reviewed immutable artifact loader. Dynamic database code execution is not authorized by this blueprint.
- **Reference selection risk — confirmed (high):** Once a reference is active, later received bars do not replace it silently, regardless of whether they satisfy reference or EMA trend criteria. `W5` is never reused after expiry; only the next received completed evaluation bar (`W6`) or a later received bar may be selected after search resumes.
- **Timeframe generalization — deferred (high):** Phase 1 remains hard-bounded to EUR/USD MID 15m. Supporting 5m, 1m, configurable timeframes, or cross-timeframe behavior requires a later explicit architecture decision and tests; builders must not add those abstractions now.
- **Phase boundary risk — confirmed (high):** Phase 1 can test target resolution with a supplied example executable entry but must not model fills, spreads, BID/ASK execution, sizing, or persist TradeIntent.
- **Worktree isolation plan — assumed (high):** After blueprint/workflow approval, use linked worktree cwd `/Users/vike/Desktop/atlas-phase-1-reference-strategy`, dedicated local branch `feature/phase-1-reference-strategy`, starting from the then-approved full SHA of the current Atlas branch. Scope is limited to `backend/domain/**`, `backend/strategies/**`, focused Strategy persistence modules, one Phase 1 migration, `backend/tests/**`, and only directly necessary README guidance; no frontend, config, dependencies, unrelated context, or OANDA files. The path must be verified absent and the source checkout inspected without altering uncommitted work. The `worktrees` skill must obtain confirmation immediately before each git command and issue a READY receipt containing root, path, branch, full SHA, scope, status, and recovery before any writer starts. No automatic commit, push, merge, prune, worktree removal, branch deletion, or cleanup. The developer owns cleanup after review; interruption recovery is to locate the worktree with approved read-only inspection, preserve files/branch, and resume or separately authorize removal—never reset or discard.
