# Exploration — Strategy / Experiment workstation

## Scope and governing context

- **Facts:** Atlas is scoped to EUR/USD, OANDA Practice, USD, 15-minute Strategy evaluation, 1-minute historical execution, and EMA Sweep Engulfing (`AGENTS.md:7-21`). Strategies are pure and environment-independent; Risk, Orders, and broker integration are outside the Strategy boundary (`AGENTS.md:43-49`; `context/architecture/strategy-contract.md:3-10,87-97`).
- **Facts:** Experiments are deterministic historical runs using canonical Strategy/Risk/Order/Fill/Position/Trade types and simulated clock/account/execution (`context/features/experiments.md:3-10`). Completed results are immutable evidence, while FAILED results are not trustworthy partial results (`context/features/experiment-results.md:7-17,51-57`).

## Dependencies and data flow

- **Facts:** Browser → `frontend/lib/api-client.ts` → FastAPI Experiment router → configuration/lifecycle/result services. Historical load is browser-triggered and durable; OANDA is used by the historical coordinator to build snapshots, while runner execution is snapshot-only. Completed run facts persist through canonical domain/persistence models, then result reads feed charts and detail.
- **Facts:** `lightweight-charts` is dynamically imported in the workflow component and configured in `frontend/vitest.config.ts:9` for tests. No additional chart abstraction is present.

## Risks

- **Fact:** Exact StrategyVersion execution depends on local implementation key plus source fingerprint (`registry.py:141-155`); unavailable provenance fails configuration/run rather than silently substituting code.
- **Fact:** Result reads can be incomplete if snapshot lineage, result row, rationale facts, or approved Risk data are missing; service returns explicit `INCOMPLETE_RESULT` or omits unverifiable facts (`results.py:193-211,341-412,488-530`).
- **Fact:** Sparse execution data can make terminal protection unknowable and fail closed (`runner.py:493-500`; diagnostics tests above). Historical gaps are persisted/disclosed and can degrade quality.
- **Fact:** `ExperimentResultReadService.price_analysis` has separate V1/V2 paths and uses `ema_100` for the legacy chart path (`results.py:249-280,579-599`), while v2 uses persisted period for the main analysis. This creates compatibility risk if a workstation expects one uniform chart contract (inference).
- **Fact:** The frontend currently hard-codes several product labels (EMA Sweep Engulfing, EUR/USD, OANDA Practice, financing excluded) despite API provenance fields (`experiment-workflow.tsx:404-410,2504-2509,2571-2577`). This may misrepresent non-reference data if scope broadens (inference; current scope is reference-only).
- **Fact:** Run command timeout is deliberately treated as uncertain (`api-client.ts:12-16,156-157`; workflow `:2431-2444`), but synchronous server lifecycle means client behavior and server completion can diverge temporarily.
- **Fact:** `result_repository.py` has no covering tests reported by CodeGraph for some direct result/detail methods; API detail/trade handlers likewise have no direct covering tests reported by the graph. Existing integration tests cover important paths but not every error-shape branch.

## Recommendations (not architecture decisions)

- Confirm the target user flow and acceptance criteria, especially whether the work is setup-centric, result-centric, or a combined workstation, before designing changes.
- Treat the persisted Experiment configuration/result and exact StrategyVersion provenance as authoritative; avoid recomputing metrics or strategy facts from current defaults.
- Preserve fail-closed status/result behavior and surface uncertainty, gaps, unavailable metrics, and provenance persistently rather than relying on transient notifications.
- Reuse existing router/service/API and chart contracts where they satisfy the confirmed scope; add tests at the domain boundary and API/UI workflow boundary for any new behavior.
- Resolve the context gaps with the product/architecture owners before implementation planning; do not infer PAPER/OANDA order behavior from the historical OANDA source adapter.
